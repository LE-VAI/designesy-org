# Designesy Labs Doctrine

## 1. Labs Purpose
Designesy Labs are the experiment layer of Designesy Intelligence Infrastructure.

Labs exist to run bounded experiments that compile into contract candidates.

## 2. What Labs Are
Labs are:
- small, inspectable experiments
- live artifacts or documented probes
- tests of motion, interaction, layout, typography, identity, workflows, review systems, and agent behavior
- a bridge between principle and reusable system rule

## 3. What Labs Are Not
Labs are not:
- blog posts
- moodboards
- random demos
- production rules by default
- generic AI template pages

## 4. Lab Lifecycle
`idea -> thesis -> artifact -> review -> extracted rules -> contract candidate -> archive or promote`

## 5. Minimum Lab Contents
Every Lab should include:
- title
- thesis
- purpose
- source basis
- live artifact or preview
- contract notes
- anti-patterns
- accessibility/performance notes
- verification result
- promotion decision

## 6. Planned Lab Categories
- Contracts
- Interface Systems
- Identity Systems
- Review Systems
- Motion / Interaction
- Source Mining
- Agent Workflows
- Creative Tools

## 7. Agent Rules
Agents must:
- keep experiments bounded
- test one behavior at a time when possible
- preserve provenance
- avoid promoting experiments into rules too early
- create review notes before contract extraction
- include reduced-motion or accessibility fallback when motion is involved
