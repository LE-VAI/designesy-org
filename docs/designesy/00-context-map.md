# Designesy Context Map

## 1. Status

- This repository is the controlled public root for Designesy Intelligence Infrastructure.
- Private and internal systems exist elsewhere and are not mirrored here.
- This repository is intended to become the source of truth for deployable public Designesy work.

## 2. Core Model

`sources → principles → contracts → tools → systems → better designed work`

## 3. System Boundaries

### Inside this repository

- public-ready doctrine
- public-ready contracts
- website/app source later
- `docs/designesy`
- Labs, Contracts, Review, Graph, and Agent Kits as future surfaces

### Outside this repository

- private internal workspaces
- raw doctrine archives
- personal files
- unstable experiments
- DNS/root registrar settings
- billing/secrets

## 4. Main Actors

- Human architect/owner
- Codex and future coding agents
- GitHub as the source-of-truth collaboration layer
- Vercel as the likely deployment layer
- Unstoppable Domains as the canonical domain/DNS identity layer
- Future visitors, creators, agents, and collaborators

## 5. Primary Surfaces (Planned, Not Built)

- `designesy.org`
- `/labs`
- `/contracts`
- `/review`
- `/graph`
- `/docs`
- `/agent-kits`

All surfaces above are planned and not yet implemented in this repository.

## 6. Governance Files

- `README.md`: repository-level orientation, scope, and current status.
- `DESIGN.md`: design contract and operating principles governing how work is created and extended.
- `AGENTS.md`: explicit operating rules and workflow expectations for agents.
- `docs/designesy`: system context, architecture, logs, and registries for design intelligence infrastructure.

## 7. Operating Rule

Internal chaos is allowed elsewhere.
This repository must remain governed, curated, deployable, and safe for agents.

## 8. Open Questions

- What is the final hosting path for all public surfaces?
- What is the final domain DNS configuration?
- What is the final Designesy identity system?
- How much of internal doctrine should become public?
- What is the long-term subdomain strategy?
- What are the final Vercel/GitHub deployment rules?
- What permission model should Codex/OpenCode agents operate under?
