# Designesy Review Doctrine

## 1. Review Purpose
Designesy Review is the quality-control layer for Designesy artifacts.

It turns taste into inspection and prevents functional-but-generic output from being treated as finished.

## 2. Review Scope
Review can apply to:
- documents
- contracts
- Labs
- interfaces
- identity systems
- agent prompts
- site pages
- visual references
- deployment changes

## 3. Review Criteria
Evaluate work using:
- Purpose
- Clarity
- Context
- Inclusion
- System Coherence
- Durability
- Delight
- Responsibility

## 4. Review Questions
For every artifact, ask:
- What is this for?
- Who does it serve?
- What source or principle shaped it?
- What contract or rule governs it?
- What anti-patterns does it avoid?
- How was it verified?
- What remains unresolved?

## 5. Visual Review Rules
For visual or UI work:
- use screenshots or previews
- compare output to reference or contract
- check desktop and mobile behavior
- inspect spacing, hierarchy, type, responsiveness, states, and accessibility
- do not treat "it runs" as done

## 6. Agent Review Rules
Agents must:
- report changed files
- report scope
- report verification performed
- report unresolved risks
- avoid claiming finality when identity, visuals, or deployment are provisional

## 7. Review Outcomes
Review outcomes:
- pass
- pass with notes
- needs revision
- blocked
- archive

## 8. Anti-Patterns
- subjective taste with no consequence
- approving screenshots without comparison
- ignoring mobile
- skipping empty/error/loading states
- adding decoration to hide weak hierarchy
- accepting generic SaaS output
- letting one-off choices become hidden doctrine
